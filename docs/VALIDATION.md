### P4 — the gap this session found

The owner's words were: *"pura ready karuga baad mei dekhuga kisko kya sell
karna hai"* — **selling** later, not **showing** later.

```
"I'll sell later"          ≠     "Nobody sees it until it's finished"
       │                                      │
  entirely fine                     this is what killed attempt #1
  no pressure, no                   by week 6 nobody knows whether
  commitment owed                   the project is still alive
```

A milestone gate only functions as a gate when someone is on the other side of
it. Demoing to yourself is a checklist, and a checklist has now failed four
times. The fix does not touch scope, does not touch Approach A, and does not
require selling anything.

## Approaches Considered

### Approach A: Fixed cadence — every 2 weeks on a set day (CHOSEN)
- Effort: S (~10 min per fortnight) · Risk: Low
- Pros: the date is the deadline; progress can slip, the calendar cannot.
  Showing unfinished work becomes normal, so there is no shame gate.
- Cons: some demos will have little new to show.

### Approach B: Milestone-triggered — demo when a gate passes
- Effort: S · Risk: Medium
- Pros: every demo contains something real; gate and demo become one thing.
- Cons: **if the gate slips, the demo slips** — which removes the forcing
  function entirely. This is precisely the failure being fixed.

### Approach C: Async — a 3-minute Loom every 2 weeks
- Effort: XS · Risk: Medium
- Pros: no calendar coordination; recording is itself a deadline.
- Cons: silence is indistinguishable from nobody watching.

**RECOMMENDATION: A** — the forcing function comes from the date, not from
progress.

## Recommended Approach

**A "demo friend" on a fixed fortnightly cadence.**

- One named person who knows coaching (a teacher, an institute admin, anyone).
- A 10-minute screen share on a set day, every two weeks.
- **No pitch. No commitment asked for. Nothing being sold.**
- Show whatever exists, including unfinished work.

This converts D3's milestone gate from self-report into a real forcing function
while leaving scope (~225 features, P1 ~95) and Approach A completely intact.
